# Hoegilab (회기랩) 커뮤니티 플랫폼 PRD (v2)

> 서비스명은 **Hoegilab (회기랩)** 입니다. "회기분석"은 학회(수업) 이름으로 그대로 쓰고, 사이트 이름만 Hoegilab으로 부릅니다.
> Claude Code에서 이 문서를 읽고 구현합니다. 기존 `hoegianalysis` 앱(QR 출석 체크 + 차수별 정산)에 **페이지를 추가**하는 작업입니다.
> 원칙: **작게 만들고, 재미있게, 글 위주로.** 사진 업로드와 외부 연동은 v1에서 제외합니다.
> v2 변경점: 출석부+성적표 상세화(세로 날짜 블록, 학기 탭), 기존 `/report` 페이지 구조 반영.

## 5. 기능 상세

### 5.1 공지사항 (`/notice`)

**목적**: 운영자가 공지와 번개 모임 안내를 대자보 카드로 올린다.

- 목록: 최신순 대자보 카드. 중요 공지는 상단 고정 + "긴급 공지" 스티커
- 카드 내용: 제목, 본문(줄바꿈 유지), 작성일, 직인
- 작성/수정/삭제: **운영자만** (관리자 비밀번호)
- v1은 **텍스트만**. 포스터 이미지 첨부는 P2 (10장)

**수락 기준**
- [ ] 운영자는 공지를 작성, 수정, 삭제, 상단 고정할 수 있다
- [ ] 일반 사용자는 읽기만 가능하다
- [ ] 모바일에서 카드가 깨지지 않는다

### 5.2 낙서 벽 (`/wall`)

**목적**: 학생들이 가볍게 한 줄씩 남기는 **글만** 쓰는 방명록.

- 입력: 별명(필수, 최대 12자), 내용(필수, 최대 140자)
- 표시: 포스트잇처럼 색과 기울기가 조금씩 다른 카드, 최신순
- 삭제: 운영자만 가능
- 스팸 방지: 같은 기기에서 연속 작성 제한(예: 30초), 길이 제한
- **사진, 링크 미리보기 없음**

**수락 기준**
- [ ] 로그인 없이 글을 남길 수 있다
- [ ] 140자를 넘으면 작성되지 않는다
- [ ] 운영자는 부적절한 글을 삭제할 수 있다

### 5.3 가고 싶은 곳 제보 (`/places`)

**목적**: 다음 탐방 후보를 학생들이 직접 제안한다.

- 입력: 가게 이름(필수), 지도 링크(선택, 네이버지도/카카오맵 URL), 가고 싶은 이유 한 줄(필수), 제보자 별명(필수)
- 각 제보에 **"나도 가고 싶다"** 버튼. 한 기기에서 한 제보당 1회만
- 정렬: 공감 수 많은 순 / 최신순 전환
- 운영자: 삭제, "다음 탐방 확정" 표시(직인 스티커)
- 별도 투표 기능은 v1에서 만들지 않음 (공감 수가 그 역할)

**수락 기준**
- [ ] 제보를 올리면 목록에 바로 보인다
- [ ] 같은 기기에서 공감을 두 번 누를 수 없다
- [ ] 운영자가 "다음 탐방 확정"을 표시하면 상단에 노출된다

### 5.4 출석 성적표 (`/attendance`)

**배경**: 기존 앱에는 모임 날짜(세션)마다 `/report/[id]` 성적표 페이지가 있다. 참가자가 출석할 때 쓴 이름을 입력하면 아래가 나온다.
- 날짜, 이름, `N/4 출석`, 성적 문구(예: "개근!"), **차수별(1~4차) 출석 여부와 분담금**, 보낼 금액, 정산 버튼

커뮤니티 사이트의 출석 성적표는 이 중 **출석 여부와 성적만** 모아서 보여준다. **분담금, 보낼 금액, 정산 정보는 표시하지 않는다** (개인 금액이라 공개 화면에 부적합).

**화면 구성 (세로 쌓기, 학기별)**
- 상단에 **학기 탭** (예: `2026-2학기`). 기본 선택은 가장 최근 학기
- 학기 안에서 **날짜별 블록이 위에서 아래로 쌓인다** (예: 10/24, 11/2 …, 오래된 날짜가 위)
- 각 날짜 블록은 카드 하나:
  - 첫 줄: 날짜 (`10/24`)
  - 표: `이름 | 1차 | 2차 | 3차 | 4차 | 성적`
  - 1~4차 칸: 출석이면 붉은 **원형 도장**(안에 "출석"), 결석이면 점선 원
  - 성적 칸: `4/4` + 성적 문구(예: "개근")
- 가로 스크롤 없이 모바일에서 읽혀야 한다 (좁은 화면에서는 도장 크기를 줄인다)
- 참고 프로토타입은 Claude 대시보드로 만들어 둔 시안이 있으며, 위 구성과 동일하다 (필요하면 운영자에게 스크린샷 요청)

**데이터**
- **기존 출석/정산 DB를 직접 읽는다. 데이터를 복사하거나 중복 저장하지 않는다.**
- 페이지를 스크래핑하지 않는다. DB에서 세션, 차수, 참석자 기록을 조회해 `이름, 날짜, 1~4차 출석 여부, 출석 수, 성적 문구`를 만든다
- 성적 문구(개근 등)는 **기존 `/report` 페이지의 로직을 재사용**한다. 기존 로직에 없는 등급이 필요하면 `lib/grade-rules.ts` 설정 객체로 분리해 숫자와 문구만 바꿔 적용할 수 있게 한다
- 차수 수가 4가 아닌 날도 있을 수 있다. **차수 수는 세션별로 가변**으로 처리한다 (표 열은 해당 날짜의 차수 수만큼)
- **학기**: 세션에 `semester` 값을 둔다. 기본은 날짜로 자동 판정(3~8월 = 1학기, 9~2월 = 2학기), 운영자가 세션별로 직접 지정해 덮어쓸 수 있다

**공개 범위 (기본값)**
- 이름과 출석, 성적만 공개한다. 분담금과 금액은 이 화면에서 제외한다
- 이름 대신 별명을 쓰는 참가자가 많으므로, 표시 이름은 출석 때 입력한 이름 그대로 사용한다

**수락 기준**
- [ ] 기존 출석 기록이 날짜별 블록으로 세로로 보인다
- [ ] 새 모임 세션이 생기면 가장 아래에 블록이 자동으로 추가된다
- [ ] 학기 탭으로 학기별 전환이 된다
- [ ] 성적 문구가 기존 `/report`와 동일하게 나온다
- [ ] 금액 정보가 어디에도 노출되지 않는다
- [ ] 기존 출석/정산/`/report` 화면이 이전과 동일하게 동작한다

### 5.5 신입생 소개 (`/freshmen`)

**목적**: 새 멤버를 데려온 사람(추천인)이 소개글을 올려 환영한다.

- 작성자: **추천인**. 카드에 "추천인: ○○" 표시
- 입력: 신입생 별명(필수), 한 줄 소개, 추천 이유, 좋아하는 음식/술, "회기분석에서 얻어갈 것"(장난 문구)
- 표시: "신규 입학" 스티커와 직인이 찍힌 **입학 허가서** 카드
- **공개 방식(기본값)**: 추천인이 작성하면 **"본인 확인 대기"** 상태로 저장되고, 신입생 본인이 확인 링크에서 "공개 OK"를 누르면 노출된다
  - 운영자 결정 사항. 단순하게 가려면 `status` 기본값만 `published`로 바꾸면 된다
- 개인정보 최소화: 실명 대신 별명 사용을 안내하는 문구를 입력창 아래에 표시

**수락 기준**
- [ ] 추천인이 소개글을 작성할 수 있다
- [ ] 대기 상태의 글은 목록에 보이지 않는다
- [ ] 본인 확인 링크로 공개 전환이 된다
- [ ] 운영자는 모든 글을 삭제할 수 있다

### 5.6 홈 (`/`)

- 대자보 스타일 메인. 상단에 `Hoegilab` 워드마크와 한 줄 소개(예: "놀고 먹자, 회기분석 학회"). 최신 공지 1~2개, 낙서 벽 최신 글 몇 개, 인기 제보 상위 3개 미리보기
- 각 기능으로 가는 큼직한 버튼 (공지, 낙서 벽, 가고 싶은 곳, 출석 성적표, 신입생)
- 선택: 공식 인스타그램 계정으로 가는 **링크 버튼 하나** (임베드나 API 연동은 하지 않음)

## 6. 데이터 모델 (새 테이블, 기존 테이블 수정 금지)

```
notices
  id, title, body, pinned(bool), created_at, updated_at

wall_posts
  id, nickname, content, device_id, created_at, is_hidden(bool)

place_suggestions
  id, name, map_url, reason, suggester_nickname, device_id,
  is_confirmed(bool), created_at

place_likes
  id, place_id, device_id, created_at
  UNIQUE(place_id, device_id)

freshmen
  id, nickname, one_liner, reason, favorite, goal,
  referrer_name, status('pending'|'published'), confirm_token, created_at
```

- `device_id`: 브라우저에 저장한 임의 UUID. 인증 수단이 아니라 중복과 스팸 방지용
- 출석 성적표는 **기존 출석/세션 테이블을 조회**한다. 학기 값이 기존 세션에 없으면 `session_semester(session_id, semester)` 같은 **보조 테이블만 추가**하고 기존 테이블은 건드리지 않는다

## 7. 운영자(관리자) 처리

- 기존 관리자 페이지/방식이 있으면 그것을 따른다. 없으면 환경변수 `ADMIN_PASSWORD`로 간단히 보호
- 관리자 기능: 공지 작성/수정/삭제/고정, 낙서와 제보와 신입생 글 삭제, 다음 탐방 확정 표시, 세션 학기 지정
- 비밀번호나 토큰을 코드와 커밋에 넣지 않는다 (`.env.local` + Vercel 환경변수)

## 8. 구현 순서 (단계마다 확인 요청)

1. 기존 프로젝트 구조 분석 + 공통 레이아웃/네비게이션 + 대자보 디자인 토큰
2. 공지사항 (+ 관리자 보호)
3. 낙서 벽
4. 가고 싶은 곳 제보 + 공감
5. 출석 성적표 (기존 DB 연동, 날짜 블록, 학기 탭)
6. 신입생 소개
7. 홈 화면 정리, 모바일 점검, 배포

## 9. 비기능 요구사항

- 모바일 우선, 로딩 빠르게 (이미지 최소화)
- 입력값 길이 제한과 서버 측 검증, XSS 방지 (사용자 입력은 항상 이스케이프)
- 기존 기능 회귀 없음: 단계마다 `npm run build` 통과 확인
- 비밀값 커밋 금지
